# Security Policy

Monero Farm Panel имеет доступ к удалённым Linux-серверам по SSH, поэтому сообщения об уязвимостях нужно обрабатывать осторожно.

## Поддерживаемые версии

| Версия | Поддержка |
|---|---|
| 1.0.x | ✅ |
| старые внутренние сборки | ❌ |

## Как сообщить об уязвимости

Предпочтительный способ — **GitHub Private Vulnerability Reporting / Report a vulnerability**, если он включён в репозитории.

Если приватный канал ещё не включён, создайте обычный Issue **без exploit-кода, секретов и подробностей, позволяющих немедленно использовать уязвимость**, и попросите владельца репозитория открыть приватный канал связи.

Не публикуйте:

- `.env`;
- SSH private keys и пароли;
- `PANEL_ENCRYPTION_KEY`;
- session secrets;
- Telegram tokens;
- дампы SQLite с credentials;
- полные логи, содержащие секреты.

## Рекомендации операторам

- Не публикуйте порт панели напрямую в Internet без дополнительной защиты.
- Предпочитайте VPN/Tailscale/WireGuard или reverse proxy с доверенным TLS.
- Используйте уникальный сильный master password.
- Для SSH по возможности используйте ключи и отдельного пользователя с минимально необходимыми sudo-разрешениями.
- Не открывайте XMRig HTTP API наружу; `127.0.0.1:60050` достаточно для SSH-модели панели.
- Храните резервную копию `.env` и `data/` в защищённом месте: без исходного encryption key зашифрованные credentials восстановить нельзя.
