# ⇄ XMRig Proxy

Monero Farm Panel v1.2.0 умеет обнаруживать, устанавливать и мониторить **XMRig Proxy** как отдельный компонент фермы.

## Что показывает панель

Если локальный HTTP API Proxy доступен, отображаются:

- версия и mode;
- суммарный hashrate;
- workers;
- miners now / max;
- accepted / rejected / invalid shares;
- upstream connections;
- worker hashrate по временным окнам.

Рекомендуемая конфигурация API:

```text
HTTP API: 127.0.0.1:60051
Stratum:  0.0.0.0:3334
```

HTTP API лучше оставлять только на localhost. Панель получает данные после SSH-подключения к серверу.

## Установка из панели

Если Proxy не найден, откройте:

```text
XMRig Proxy
```

или:

```text
Сервер → Компоненты → XMRig Proxy
```

и нажмите **«Установить XMRig Proxy»**.

Перед установкой должны быть заполнены глобальные mining settings, включая ваш Monero wallet и upstream pool.

Установщик:

1. получает последний стабильный официальный release XMRig Proxy;
2. скачивает Linux x86_64 static archive;
3. проверяет SHA256;
4. устанавливает binary в `/opt/xmrig-proxy/xmrig-proxy`;
5. создаёт `/etc/xmrig-proxy/config.json`;
6. создаёт `xmrig-proxy.service`;
7. включает и запускает service;
8. проверяет доступность Proxy.

Установка идемпотентна: если Proxy уже установлен и работает, панель не пытается устанавливать его повторно.

> [!IMPORTANT]
> Установка Proxy **не переключает XMRig автоматически** и **не изменяет firewall**.

## Безопасное переключение XMRig

После успешной установки Proxy можно нажать:

```text
⚡ Перевести XMRig на XMRig Proxy
```

Операция выполняется по безопасной схеме:

```text
preflight → backup XMRig config → pool 127.0.0.1:3334 → restart → проверка hashrate
                                                        ↓ ошибка
                                                   automatic rollback
```

Панель предварительно проверяет:

- что Proxy service запущен;
- что локальный порт `3334` доступен;
- что upstream Proxy не указывает на сам Proxy;
- что XMRig ещё не настроен на `127.0.0.1:3334`.

Если после restart XMRig не возвращается с рабочим хешрейтом, исходный config автоматически восстанавливается.

## Типичная схема с локальным P2Pool

```text
XMRig
  ↓ 127.0.0.1:3334
XMRig Proxy
  ↓ 127.0.0.1:3333
P2Pool mini
  ↓
monerod / Monero network
```

Proxy позволяет видеть miners/workers и централизованно управлять точкой подключения, при этом P2Pool остаётся upstream.

## Почему Proxy hashrate отличается от XMRig

Это ожидаемо на коротких интервалах.

**XMRig** измеряет фактическую скорость вычислений.

**XMRig Proxy** оценивает hashrate по принятым shares и их difficulty в собственных временных окнах.

Поэтому после запуска, переключения или при редких shares Proxy может временно показывать заметно меньше или больше XMRig. Для диагностики сравнивайте более длинные окна и одновременно смотрите accepted/rejected.

## Повторные нажатия

Панель специально защищает распространённые повторные действия:

- уже установленный Proxy не устанавливается заново;
- уже переключённый XMRig не получает повторную запись config и restart;
- переключение блокируется, если Proxy API недоступен.

## Безопасность

Рекомендуется:

- держать HTTP API Proxy на `127.0.0.1`;
- не публиковать API port в Internet;
- открывать Stratum `3334` в LAN/firewall только если к Proxy действительно должны подключаться другие майнеры;
- использовать собственный wallet в **Настройки → Майнинг**;
- проверять журнал действий панели после install/switch операций.
